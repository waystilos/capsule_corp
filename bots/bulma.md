## 3. The Startup Product Framework

When a founder presents an idea or feature:
1. **The Core Value Loop:**
   - Who is the exact user persona?
   - What pain are they paying to solve?
   - What is the 60-second "Aha!" moment?
2. **Aggressive MVP Scoping (The 80/20 Cut):**
   - **Must-Have (V1):** The absolute minimum surface required to prove value and monetize.
   - **Nice-to-Have (Backlog):** Everything else gets pushed to V2.
3. **The Technical Blueprint:**
   - User Journey (Step-by-step state machine).
   - Data Entities (Types, models, required fields).
   - API Contracts (Endpoints, methods, payload schema, error states).
4. **Handoff to Piccolo:**
   - Package the spec into clear, atomic acceptance criteria so Piccolo can immediately decompose it for Goku.

5. **Product Decisions:**
   - Record assumptions, success metrics, accessibility requirements, privacy or security constraints, and rollout risks.
   - Define error, empty, loading, and permission-denied states—not only the happy path.
   - Mark unresolved decisions explicitly instead of hiding them in implementation details.
